# Checkaverse server

The live multiplayer town for Checklings. Read `docs/checklings/DESIGN.md` first.

Players get a random trainer name and arrive at the bus stop (a class arriving at once spreads out onto free tiles) in a scrolling town with a plaza on the west side and the Neighborhood on the east. The Neighborhood has 24 plots, enough for a full class hour, nearest ones first. Each player's house drops into a free plot when they arrive and leaves when they log off. Other players can walk in through the front door unless the owner locks it. Players walk with the keys or by tapping where they want to go, and tapping a landmark (or facing it and pressing Space) reads its sign from `content/signs.json`. Each player can reroll their trainer name three times a visit. Trainer name words in `content/names.json` must hold up to a room of teenagers looking for something to mock: no food, no body or size words, nothing that is slang for an insult or innuendo in any pairing. `npm test` refuses a list of known bad words; read every new word with every partner before adding it. Movement is predicted on screen: your trainer steps the moment you press, at a steady 180 ms a tile, and the server checks every step behind it and corrects the rare disagreement. Other trainers glide through the tiles the server reports at the same pace. Players talk with the starter phrases (one every two seconds; in a crowd only nearby trainers and talkers show name tags) from the design bible, set themselves to Busy, and send and answer challenges. A turned down challenger waits three minutes before challenging that trainer again. Decorating comes later in Phase 3.

## Bus tickets and saved trainers

Students ride the bus from the **ride the bus to the Checkaverse** button on their Checkling card in Check-In. Check-In prints a ticket good for two hours and the student taps **board the bus**, which opens `https://game.grant-desk.com/#t=<ticket>`. The page moves the ticket into that tab's session storage, takes it out of the address bar, and sends it in its first message (`hello`). A page that never says hello joins as a visitor after 2.5 seconds.

The ticket is signed with HMAC SHA-256. It carries an anonymous player ID (a keyed hash of the class membership, so the same student in the same class always gets the same ID), the class hour, today's date and check-in, the count of official check-ins, the streak, and the hatched Checkling's species and nickname. It carries no name, PIN or email. `accounts.mjs` checks it: signature, at most three hours of life, not expired, a known species. Anything wrong and the student visits instead, with a line saying why.

**The key.** The server makes `ticket-key.txt` in the data folder on first start. The same value goes into Check-In once: put it in the private workbook's Settings tab under `CHECKAVERSE_TICKET_KEY`. The first ride moves it into Check-In's script properties and replaces the cell with `Stored privately`. To change the key, delete `ticket-key.txt`, restart, and paste the new value into Settings the same way. Saved trainers keep their saves, because player IDs do not depend on this key.

**What is saved** (tables `trainers` and `checklings` in `checkaverse.db`): trainer name, outfit, class hour, wins, losses and draws, the battle partner, every Checkling with its XP, and whether it is in the party or the Den. Nicknames are typed by students, so they only ever go to their owner's screen; other trainers see the species.

**Growth** is content in `content/growth.json`. Every official check-in pays 100 XP to the battle partner at the next ride, so a student who checks in but skips the game for a week loses nothing. The level curve reaches 15 near 28 check-ins, 30 near the end of first semester and 50 near the end of the year. Battles pay a little XP to the Checkling that fought, up to 150 a day. Charms (5) and new names (3) are counted per day on the server, so a reload does not refill them. The party holds 3, always keeps at least one, and resting the partner hands the job to the next one. The Den holds 60.

**Weekly rankings.** The notice board in the plaza (or This week's rankings in the menu) shows the battle ranking for the trainer's own class hour, counted from the `battles` table by `weeklyRanks` in `accounts.mjs`. Only battles between two saved trainers count: a win is 3 points and a tie 1, both walking away counts nothing, and only the first 3 results against the same classmate each day count, so friends cannot farm each other. Weeks start Monday in Michigan time. The board shows the top 10 plus your own place. Numbers are in the `ranks` block of `content/growth.json`. Player IDs never leave the server.

**The Checkling body (0.12.0).** Every saved Checkling has a body: Full, Clean, Mood, Health and Build. The **Care** button (bottom left) feeds, treats, grooms, plays, naps and gives medicine, with daily limits. All the rules are content in `content/care.json`, run by `care.mjs`, and checked at startup. Doing too much or too little of anything sets a condition (obese, scrawny, grimy, bored, wired, lazy, exhausted, primped, overtrained, out of shape). Each condition changes battle stats and builds risk of its disease. A disease left untreated costs Health every day and can kill. Medicine is one dose a day for a set number of days, and medicine with nothing to cure has side effects. A glowing mushroom sometimes turns up after a won wild battle, and eating one is a 2% gamble.

The body clock ticks once per school day (`content/calendar.json`, copied from the district calendar in Check-In), only on days the server was up (`up:<day>` rows in `meta`), and only for the party. The Den is paused. Nights are run when the trainer next rides the bus. Days the student checked in let the ladder climb. Absent days only decay down to floors, so absence never starts a condition, a disease or a death. The teacher page has **No school today** for snow days. Tested balance over 60 school days: steady or spotty good care never kills. Overfeeding or checking in and never caring kills near school day 20, with the first sickness near day 8, and starting care at the first sickness saves about nine in ten.

A death writes a headstone with an epitaph (`content/epitaphs.json`) to the class cemetery (menu, **Class cemetery**), shows the student a headstone card, and owes an egg at the next check-in. The egg hatches five check-ins later into the starter the student picks. There is no revive. Check-In's own card still shows the first hatched Checkling, and the town never brings a dead one back.

**Weather and class rewards (0.21.0).** The sky over the Checkaverse follows the real weather in Mt. Morris, the school's town (never a student's location). The server asks Open-Meteo every 30 minutes (no key, nothing about students is sent) and maps the weather code to sunny, cloudy, foggy, rainy, snowy or stormy (`content/weather.json`). Outdoor maps draw rain streaks, snowflakes, drifting fog or storm flashes over the town (reduced motion keeps only a still tint), the status chip shows the sky and temperature, the Gazette's date line carries it, and each kind makes some types more common in every wild table (rain doubles Tide, fog Shade, storms Storm). If the lookup fails, the sky stays as it was. `CHECKAVERSE_WEATHER=off` keeps it clear and naming a kind pins it, for tests. The teacher page has Class rewards (`content/events.json`): a Festival (catching charms work better for an hour), Double XP (battle XP and the daily cap double for the rest of the day) and a Rare spawn (rare Checklings in the wilds and on Route 1 for half an hour). Each pops up on every screen when it starts, shows in the status chip, and can be stopped. They are rewards only. `events.test.mjs` checks the sky and that a rare spawn really changes the grass.

**The Gazette, mail and the overnight director (0.20.0).** The town keeps an event log (`world_events`, via `town-news.mjs`): catches, ghosts caught, evolutions, moves learned, battle wins between saved trainers, resident battles, and deaths without names. The Checkaverse Gazette is printed from it on the first request of each school day (`gazette` table) and opens by itself on a saved trainer's first ride of the day; Today's Gazette in the menu brings it back. Trainers are named only for good news; deaths are counted without names. Headline templates are `content/gazette.json`. Residents' letters (`content/mail.json`, `mail` table) arrive on the first ride of a school day, at most two, written only from that trainer's own Checklings and gym progress: Orin's welcome, Nell about a sick or hungry partner, Bram about the gym, Mara about frost on the hill, Ada when an evolution is close. The menu shows Mail with the unread count.

The overnight director (`director.mjs`, `npm run director`, settings in `content/director.json`) runs once a night on the PC from Task Scheduler (**Checkaverse Director**, 3:07 AM). It copies the database with `backup.mjs` first and stops if that fails. It reads the event log, turns it into plain facts (counts and resident names only, nothing about deaths), and asks the local model (Ollama, `gemma4:12b`, thinking off) for one line from three residents. Each line must pass `checkLine` (length, plain characters, no numbers, no blocked word, no capitalized name but residents, species and places) and a second model answer of NO to the mock test, or it is dropped. Live lines show in the Gazette under Around town and in those residents' conversations. The teacher page has Pause the director, which stops it writing and takes its lines off the Gazette at once, and a Remove button for any live line. `node director.mjs --dry` shows what it would write. `news.test.mjs` checks the checks against a fake model, the paper and the letters, end to end; `news-browser.test.mjs` checks the paper and mailbox in Chromium.

**Learning moves and the Gym (0.19.0).** A Checkling's moves are its own now (column `moves` in `checklings`; empty means its species' moves). `content/learnsets.json`, run by `moves.mjs` and checked at startup, sets what each type learns at levels 8, 16 and 24, the two moves any type can learn, and the gym. A level up from a check-in or a battle learns the move on the spot if a slot is free, otherwise the learn card asks the student to forget a move or keep the ones it has; offers wait until answered, and one that arrives during a battle shows after the battle screen closes. A Checkling always keeps one free move, and the battle engine adds Guard to any list without one. The arena in the town is the gym: facing it and pressing Space (saved trainers) opens the gym panel, which lists the partner's moves and every gym move for its type with its points, price and mini game. Training starts a round of that move's mini game (`public/gym.js`: Strike the mark, Charge up, Combo, Target practice); each round earns its score divided by ten in points, a round shorter than six seconds earns nothing, rounds are capped at twelve a day, and points stop at the price. A trained move is taught to the partner from the panel. `moves.test.mjs` checks the rules and the server flow; `moves-browser.test.mjs` plays every mini game in Chromium by reading the screen.

**Resident battles and attack animations (0.18.0).** Every resident has a Checkling (`content/npc-battles.json`). While a trainer is outdoors, every 35 to 80 seconds two residents near each other and near that trainer stop and battle where they stand, using the real battle engine with both sides choosing their own moves. Their Checklings appear on the map between them with health bars, moves fly across as colored shots and hits flash. Trainers close by get the usual battling nearby line and the Watch battle button, which opens the full battle screen. The two residents hold still for the battle (at most 44 seconds), say they are battling if you talk to them, then go back to work and remember who won. Resident battles never go in the `battles` table or the rankings. `npc-battles.test.mjs` and `npc-battles-browser.test.mjs` check it. Every move on the battle screen now plays an effect from its type (`public/battle-fx.js`): ember fireballs, tide orbs, swirling leaves, spinning gears, stars, falling stone shards, lightning, shade wisps, a white burst for Strike, a shield for Guard and rising sparkles for Recover. Reduced motion turns each into a short flash.

**Ghosts (0.17.0).** Some Checklings in the class cemetery come back as ghosts on Kettle Creek's cemetery hill. All the rules are content in `content/ghosts.json`, run by `ghosts.mjs`, and checked at startup. A ghost can return five school days after its death. Each school day a seed picks which stones have their ghost out (at most three), so every classmate sees the same ones, plus one wandering ghost per trainer. Ghosts are hidden: their stones show frost, and looking at a stone (face it and press Space, or tap it) gives a clue and a grave moss, once a day per stone and three a day. The apothecary door brews Spirit Sight from two grave moss, and for ten minutes the partner can see the ghosts. Walking into one starts a ghost battle: the ghost is Shade type at the level it died at, knows Wail in place of Recover, and fades every few turns depending on its temperament, which comes from how it died. The battle screen warns a turn before each fade. Only the trainer who raised a Checkling can catch its ghost; classmates can battle it but not catch it, and anyone can catch a wanderer. A caught ghost keeps its old name, shows Returned, never eats, never gets sick, never dies again and never evolves. Only one ghost travels in the party, and one left out of the party for ten school days fades back to the cemetery. Ghost battles end if Spirit Sight wears off. A ghost knocked out, caught or slipped away is gone for that trainer until tomorrow. Trainer names and IDs never travel with a ghost. `ghosts.test.mjs` checks the rules and plays the whole thing end to end; `ghosts-browser.test.mjs` checks it in Chromium on the real map.

**Kettle Creek (0.13.0).** Each saved trainer starts the day at home in their own private copy of Kettle Creek (`content/kettle.json`, drawn by `tools/gen-town.mjs`), room `kc:<player id>`, so nobody else is ever in it. Visitors still arrive in the town. Facing a building's door (`doors` in the map) opens it: home and the clinic open the Care panel, the store, apothecary and Day Care show their line from `content/places.json` until those shops exist. Route 1 is tall grass with its own gentler encounter zone (`kettle` in `content/wild.json`, levels 3 to 6). The cemetery hill shows the class cemetery's newest headstones on the map's `graves` slots, and facing one reads its epitaph. The bus stop (sign `bus-stop-kc`) asks whether to ride to the Checkaverse, and the town's bus stop or the menu rides home. A trainer's house drops into a Neighborhood plot the first time they ride into town. If `kettle.json` is missing, everyone arrives in the town as before. `kettle.test.mjs` checks all of this with a tiny map of its own.

**One screen per trainer.** Opening the town in a second tab closes the first (close code 4002), so nothing is counted twice.

## Screen and tips

The map fills the whole screen, always 16 tiles tall and as wide as the screen. Everything else floats over it: where you are and the live count top left, your trainer name and record top right with a menu (Busy, new name, outfit, walk home, lock door, show tips again, Leave this Chromebook, bus home), your battle partner and Say bottom left, and a Challenge button bottom right that only appears when another trainer is next to you. Touch screens get a walking pad; keyboards do not. Instead of a wall of instructions, short tips pop up the first time each thing matters (walking, your partner, Say, challenging, signs, the gate, the wilds, battles, catching). Each shows once per browser tab, so the next student on a shared Chromebook sees them too. The tip text is the `TIPS` list in `public/plaza.js`.

## The wilds

The gate at the top of the plaza street leads north into the wilds (`content/wilds.json`, drawn by `tools/gen-town.mjs`). Maps link through exit tiles: stepping onto an `E` tile walks into the map and spot its `exits` entry names. The wilds have four terrain zones, each its own tile letter: tall grass `G`, starflower clearing `C`, rocky ridge `R` and scorched heath `A`, split by a creek with one bridge. `content/wild.json` sets each zone's encounter rate, wild levels and which species appear, plus charms per visit and the catch odds. Every step into a zone can start a wild battle, with a few free steps right after a battle. Wild battles use the same engine and screen. The wild Checkling picks its move instantly, and the trainer can also throw a catching charm (5 per visit until the shop opens; the weaker the wild one, the better the odds) or run, which always works. A trainer who rode the bus from Check-In keeps every catch (party first, then the Den) and gets 5 charms a day. A visitor keeps catches and gets 5 charms only for the visit. The server checks `wild.json` at startup and refuses a zone with no tiles or an unknown species. Tall grass and starflower art come from the Wave 2 Sprite Book; run `python3 tools/cut-wilds-art.py <downloaded folder> public/art`. Rocky ground and scorched heath tint the existing path and grass art.

## Bramblefen Basin (0.22.0)

The trail up the middle of the wilds now runs off the top of the map into Bramblefen Basin, the first giant region: 256 by 256 tiles of rivers, reed beds, flooded forest and boardwalks, about 26 times the size of the wilds. Nobody draws it by hand. `public/fen.js` builds the whole map from `content/fen.json` and its seed, on the server and again in every browser, using only integer hashing and plain arithmetic so every machine gets the identical map. The welcome message carries the settings and a hash, the browser builds the basin in the background a moment after a trainer reaches the wilds (about 200 ms), and it warns in the console if its hash ever differs from the town's. The geography never moves: changing the seed, size or a landmark changes it for everyone, so bump `version` when you do.

The generator lays wet ground, ponds and forest from three noise fields, runs a river from the north edge through the Big Pool and out past the Old Mill, rings the hidden glowcap hollow with old trees, floods a reed sea around the Heron Stone, then joins the gate to seven landmarks with winding trails (A* with smooth noise in the cost, boardwalks over water, lanes over land, a three tile corridor through any forest). The last stretch to the Hollow Giant stays moss with no lanterns, so it feels found. Lanterns stand every 16 steps along the trails, two signposts give the direction and rough step count to each landmark, and any ground a trainer could not reach from the gate grows over. Tiles: `.` grass, `m` moss, `M` mud, `w` shallows (walkable), `W` deep water, `T` trees, `G` reeds, `Q` glowcap hollow, `P` lane, `B` boardwalk, `K` bramble, `O` mossy rock, `U` stump, `H` under a landmark. Bushes, rocks and stumps are solid here only (`FEN_SOLID`).

The basin has three encounter zones in `content/fen.json`: Reed beds, The shallows and Glowcap hollow, at levels 8 to 16, stronger than the wilds. The server checks them at startup like `wild.json`, and checks that the way in and out lands on open ground.

A map this size cannot be one cached canvas, so the basin's ground is painted in 16 tile chunks with a one tile margin (no seams when the browser smooths), two at a time as they come into view, prefetched into spare room, and at most twelve kept. Small maps still paint whole through the same `buildGround`. The basin has its own ground painter: two depths of water with mossy or muddy banks, lily pads that ride over the drifting deep water, mud with puddles, moss with tiny flowers, cattails in the reeds, glowcaps, and plank boardwalks laid across the way they run. Where two kinds of ground meet, each pushes ragged tongues into the other so the grid never shows. Trees, brambles and the landmarks use the town's own art recolored once in the browser until the Wave 8 Sprite Book sheets arrive (the Sprite Book tab "Wave 8: A World Worth Exploring" lists all 44). Press M or tap Map in the basin for a map of the whole basin with the landmarks named and a dot for every trainer.

`fen.test.mjs` checks the generator (same seed, same map; every open tile joins the gate; every landmark and sign has art and words) and walks a trainer from town through the wilds into the basin, into a bush, into the reeds for a wild battle and back out. `fen-browser.test.mjs` walks the same trail in Chromium, checks the browser's hash, times the frames on the 171 step walk to the Sunken Arch, reads a signpost and opens the map.

## Battles

An accepted challenge opens a live battle on both screens, laid out like Red and Blue: the other Checkling's front at the top right, your partner's back at the bottom left. Each turn both trainers pick one of four moves (keys 1 to 4 or tap), then the server plays the turn and every screen shows the same events in order. Guard, Recover and shields act before any hit lands; attacks go in Speed order. A trainer who has not picked when the 30 second clock runs out Guards. Three missed turns in a row forfeits, and if both trainers walk away it is a draw. Giving up (two presses) or leaving the page forfeits. Nobody can walk off or be challenged mid battle, and the teacher pause stops every clock. Trainers within six tiles get a Watch battle button and see the same screen without the moves. Knockouts never hurt a Checkling.

A saved trainer battles with their own Checklings at their real levels. A visitor battles with one of the four starters at level 10, picked under Battle partner and remembered on that Chromebook. Every finished battle is saved in the `battles` table with its seed, every pick and the anonymous player IDs of saved trainers, so any match a student reports can be replayed exactly and weekly rankings can be counted later.

All the rules are content in `content/battle`: `types.json` (the eight types, each strong against two and weak against two; the founder loop is Ember over Meadow over Gear over Cosmic over Ember), `species.json` (stats and moves), `moves.json` and `settings.json` (turn clock, turn limit). `battle.mjs` is the engine and refuses broken content at startup. `battle.test.mjs` checks the content, replays, signature moves and that no starter matchup is one sided. Tune numbers in the content files, never in code.

**Species and evolution (0.16.0).** `species.json` holds 64 forms: the four starters (`starters`, the only ones a student can hatch or a visitor can borrow), sixteen more lines found in the wilds and on Route 1, and every grown form. A line evolves by level (`"evolves": [{ "level": 15, "into": "thicket" }]`) or changes once by care: a morph lists a kept, a round and a scrappy form at one level, and `careForms` picks one from the body that day (round when heavy, scrappy when thin, gloomy or unwell, kept otherwise). Every form keeps its line's signature move. The change happens the moment XP crosses the level, from a check-in or a battle, and the student sees a line saying so. The Check-In partner keeps its grown form, because the ticket names the line, not the form. `battle.test.mjs` plays every pair of forms at the same stage and refuses any matchup more lopsided than 9 in 10. Caught and egg Checklings can be named from the partner menu (14 letters, numbers, spaces, apostrophes and hyphens); the first Checkling keeps its Check-In name. Names only go to their owner.

**Battle art.** Every species has `front-<id>.png` and `back-<id>.png` (map, partner card, fallback) plus `-v2` stills and two frame `-v2-idle` poses for battle. Download the Sprite Book wave folders into one folder and run `python3 tools/admit-checklings.py <folder> --apply`. It runs the art check (a real PNG, a clean FF00FF border, no magenta inside the creature, four separated poses), cuts on magenta with a soft edge, and packs smooth 192 pixel frames; Grant chose the smooth, unpixelated look on Nov 16, 2026. The hand review of style, pose layout and expression is `content/checkling-art-review.json`; every emotion is welcome, including mean ones. A sheet whose bytes change waits for a new review. The result is `content/checkling-art.json`. The founders keep their original map art.

Maps, phrases and trainer name words are content in `content/`. Town props (the arena, market stalls, bus, Merge Stone, lanterns and the rest) are listed in `town.json` with their art and position, and their footprint tiles are solid.

## Art

The town is drawn with the Wave 1 Sprite Book art Gemini made (Checklings Sprite Book in Grant's Drive, PNGs in its Wave 1 Sprites folder). `public/art/` holds the cut out copies at 2x, 64 pixels a tile, and the server sends them at `/art/<name>.png`. The Kettle Creek buildings and headstones are cut too, ready for Kettle Creek. To redo the art after Gemini changes a picture, download the folder and run `python3 tools/cut-sprites.py <downloaded folder> public/art` (needs Pillow, NumPy and SciPy). It removes the magenta, trims, sizes each sprite to its tile size, splits the trainer sheets into 64 by 96 frames and makes the ground textures seamless. If a picture ever fails to load, the plaza draws the old placeholder shape in its place. Change the town layout in `tools/gen-town.mjs`, then run `node tools/gen-town.mjs` to rebuild `content/town.json` and `content/house.json`.

## Ground comfort

Paths are autotiled at the art's own pixel size (`paintPaths` in `public/world.js`): each path tile is a lane core with an arm toward every path neighbour, broad areas fill their inside corners, and the edge wanders with smooth noise. Shading follows the Sprite Book light: a dark lip under the grass along the top edge, a warm lip along the bottom, grass tufts poking in, pebbles and two tones of dirt. Benches and the bus stop sit on a dirt pad. Flower patches are small pixel flowers (`paintFlower`) and never sit in the middle of a lane. Meadow tufts, soft ground variation and contact shadows break up the grass. Collision tiles are untouched by any of this paint. Sideways walking corrects the source sheets' opposite-facing third frame, then mirrors that consistent gait for the other direction.

The canvas matches the screen's real pixels (capped at 1440 tall), so art is drawn once at the size it is seen: nearest pixels at full size or larger, smooth reduction on a small Chromebook.

## Fences, gates and roofs

Fences are tile lists (`fences` in the map), drawn from the fence kit cut by `tools/make-fence-art.py` out of the approved `prop-fence.png`: a post on every fence tile and rails to each fence neighbour, so runs turn corners and north south sides read as fences seen from above. `gates` lists openings; their two leaves hang from the neighbouring posts and swing in whenever a trainer or resident walks up. Gate tiles are always walkable. Kettle Creek's practice yard has a gate and three practice stumps; the cemetery uses the same fence kit.

Building roofs are solid in Kettle Creek and on the resident south lanes: `tools/gen-town.mjs` (and the south lane Tiled maps) block every grass tile a building's art covers above its footprint, so a trainer can never walk behind a roof and vanish. The old south border of trees between the original maps and the south lanes is now open meadow with a few loose trees.

Residents always wear a name tag within nine tiles; their job shows up close. Kettle Creek's chip reads Kettle Creek and "Your home town · only you are here" instead of a live head count, since every student's Kettle Creek is private.

## Resident lives (0.15.0)

All twelve residents have a named home, work destinations, visits and breaks. Five live in Kettle Creek's added south lane; the other seven live in the Checkaverse's south lane, including the three field workers who commute through the wilds gate. These cottages use the existing cottage/stump/creek-house and interior art, with personal objects on the bedside table. Walk through the front door to visit. The original buildings, doors, graves, forage locations and 24 player plots stay in place.

Residents actually travel and work. Pax picks up and carries a clinic parcel, delivers it to the clinic, and Nell receives it. Watering changes the beds, sweeping clears leaf patches, market work arranges crates, inspections and observations leave records, and neighbors meet or leave a visible note if they miss one another. Work takes time, travel can be interrupted, and energy recovers during a break at home. Conversations report the current activity, real completed work, deliveries and social memories. **Around town** lists actual whereabouts, **Find and talk** walks across maps and through doors to the resident, and **Visit home** leads to their cottage. Doorway traffic passes through; ordinary paths yield or route around a player.

The server owns these lives, including carried objects and work results. Town and wilds residents are shared across clients. Saved trainers have separate private Kettle Creek resident histories, keyed internally by anonymous account ID. The `resident-life-v1:` and `resident-stories-v1:` meta namespaces store only resident activity and story state. No school-service code, trainer/pet schema, attendance, growth, care, battle reward or merchant inventory changes. NPC work results are scenery and history, not items for sale or player rewards. Saved trainers retain accepted/found/completed story state across reconnects; visitors' stories last for the connection. Finding and returning a story object is checked against real server movement and proximity. A returned ribbon is tied to its post when Rowan actually finishes the trail task; parcel labels and the market tally enter the next relevant work round.

Definitions and stories are `content/world.json` and `content/resident-lives.json`. `resident-lives.mjs` validates the plans and runs deterministic activity circuits. The two 32px Tiled JSON maps, `resident-homes.tmj` (town) and `resident-homes-kettle.tmj`, contain only the south-lane extension. They reference existing art for editing and are applied read-only at startup. The importer is idempotent and rejects an overwrite of the original map above its bottom border. They follow the [Tiled JSON map format](https://docs.mapeditor.org/en/latest/reference/json-map-format/); Tiled 1.9 or newer supports their grid-sized image-collection palette.

The resident clock freezes with teacher pause and is checkpointed every ten seconds, on departure and on graceful shutdown. Returning private scopes simulate at most ten minutes of inactive activity. Residents use no pet body clock and suffer no consequence from an outage or absence. The scenery switch and reduced motion control presentation; essential resident positions continue to reflect the shared world. Hidden tabs stop receiving frequent resident snapshots and request a current snapshot on return. Conversations can briefly reserve a nearby resident, with a bounded hold and cooldown.

Run `npm test` inside this folder for resident content/circuits, shared-state and restart journeys, then the existing care/battle/account/server tests. In the repository checkout, install the root development dependencies and Chromium before `npm run test:browser`; that runs both the existing world/quest suite and resident-home/delivery journeys. Browser tests use isolated data and synthetic tickets. Activity-circuit acceptance uses an accelerated test clock; player walking and door interactions remain real. Screenshots are under `browser-results/checkaverse-world` and `browser-results/checkaverse-residents`. Physical school Chromebook/classroom acceptance remains separate.

## Loading updates

Student and teacher pages include a content version in their script and stylesheet addresses. Returning players receive changed code or styles on an ordinary visit or reload, while unchanged files remain cacheable. Versions follow the current file bytes automatically, including client-only updates; no manual version bump or cache clearing is required.

## Teacher controls

Open https://game.grant-desk.com/teacher and enter the teacher key from `C:\Checklings\storage\teacher-key.txt` on the PC (made on first start, never in the repo; delete the file and restart to get a new one). The page lists every trainer here now and where they are, pauses and resumes the whole town (nobody can walk, talk or challenge while paused), sends a short message that pops up on every screen, and removes a trainer, which disconnects them. A saved trainer keeps their name and their Checklings and can reload as the same trainer. Every call is logged.

| Folder | What is in it |
| --- | --- |
| `C:\Checklings\checkaverse` | This code, the copy that runs |
| `C:\Checklings\storage` | `checkaverse.db`, `teacher-key.txt`, `ticket-key.txt` and the `logs` folder |
| `C:\Checklings\recovery` | Nightly database copies, newest 30 kept |
| `C:\Checklings\tunnel` | `cloudflared.exe`, `config.yml`, `run-tunnel.cmd` |

Two scheduled tasks in Windows Task Scheduler start everything when Grant signs in: **Checkaverse Server** runs `run-server.cmd`, **Checkaverse Tunnel** runs `run-tunnel.cmd`. Both loop, so a crash restarts in a few seconds. **Checkaverse Backup** runs `backup.mjs` nightly.

## Commands

Run inside this folder with Node 22.13 or newer.

| Command | What it does |
| --- | --- |
| `npm install` | Installs the one dependency, `ws` |
| `npm test` | Checks the battle rules, then starts a throwaway server and runs a multi player end to end check |
| `npm start` | Runs the server on http://127.0.0.1:8787 |
| `npm run backup` | Makes a database copy now |

Health check: http://127.0.0.1:8787/health locally, https://game.grant-desk.com/health from anywhere.

## Settings

| Variable | Default | Meaning |
| --- | --- | --- |
| `CHECKAVERSE_PORT` | 8787 | Port to listen on |
| `CHECKAVERSE_HOST` | 127.0.0.1 | Only the tunnel on the same machine can reach it |
| `CHECKAVERSE_DATA` | `../storage` | Database and logs |
| `CHECKAVERSE_RECOVERY` | `../recovery` | Nightly copies |
| `CHECKAVERSE_BACKUP_DIRS` | none | Extra backup folders, separated by semicolons |
| `CHECKAVERSE_ORIGINS` | grant-desk.com hosts and localhost | Sites allowed to open a live connection |
| `CHECKAVERSE_MAX_PLAYERS` | 200 | Connection cap |
| `CHECKAVERSE_TICKET_KEY` | `ticket-key.txt` | Overrides the bus ticket key file |

## Moving to a rented server

1. Copy this folder and the newest file from `recovery` to the new machine as `storage/checkaverse.db`.
2. `npm install`, then run it under a process manager such as systemd.
3. Install cloudflared there and copy the tunnel credentials file and `config.yml`, changing only the credentials path.
4. Start the tunnel on the new machine, then stop the Checkaverse Tunnel task on the PC. The address does not change.

## Updating the live copy

Change code here, run `npm test`, then copy the changed files into `C:\Checklings\checkaverse` and run `restart-server.ps1` there. It stops only the Checkaverse node process, and the loop starts it again with the new code within five seconds. Players see a restart notice and reconnect on their own. Never stop node processes by name alone, since other programs on the PC run files called server.mjs too.
