# Recovery and updates

- Keep your private classroom spreadsheet and its existing web app link. Students' logs and attendance live there.
- A failed or unavailable directory must never fall back to old generated PINs. Use teacher backup controls while the coordinator restores directory access or repairs the source.
- Before changing the school directory, make a private spreadsheet copy. Keep numbers stored as plain text. Restore a mistaken directory edit using Google Sheets version history, then test with synthetic identities. Students who were never assigned to this classroom still cannot enter.
- Before a software update, privately copy the classroom workbook and retain the existing Apps Script version. The source files in this ZIP contain no school data. School IT can replace the program in the existing bound project, save a new version, and update the existing deployment. Keep DOMAIN access and USER_DEPLOYING execution. Do not create a replacement student link.
- Code updates require a new Apps Script deployment for each independent copy; shared directory corrections are read automatically. Your teacher dashboard's directory panel reports the installed software version.
- Returning to an earlier software version does not require deleting class memberships, logs, or the directory. Never delete those tabs to repair the app. Resolve an uncertain network request from the live teacher dashboard before entering the same PIN again.
