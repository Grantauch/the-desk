Owner: Codex. Branch: `checklings/batch-05-school-bridge`, stacked on Batch 04 PR #229. Source implementation and synthetic tests; **not configured, mounted, deployed or verified with actual school accounts**. Batch 06 owns isolated hosting and real navigation acceptance. No student records have been imported.

## Delivered behavior

- The existing five-file Apps Script source now recognizes `mode=checklings` for an independent game launch. It validates the broker-signed 60-second ticket before requesting a fresh PIN, uses the existing school-account guard/PIN verifier and attempt limits, and returns only that identity's enabled classes. The student explicitly confirms a class before a user-activated return link appears.
- The game selection proof uses a separate signing domain, is bound to the exact ticket and school-account context, expires within 60 seconds and is invalidated by PIN changes. It cannot authorize attendance or a pass. No Hall Pass session or action proof is created or forwarded.
- The school privately sends a complete per-class authorization snapshot, then the existing one-use launch assertion. The game receives HMAC-derived tenant-scoped member/class identifiers, a separately hashed credential version, active/pause state and bounded times. It receives no real name, email, PIN, PIN hash, classroom session, attendance, workbook identifier or Google credential. The class-specific credential fingerprint does not link one student's different memberships.
- An additive SQL migration 004 stores class authorization leases, adds membership credential versions and appends immutable consequential access events. New snapshots create missing opaque memberships; credential changes, pause/reopen, and omitted/deactivated roster memberships increment epochs and revoke sessions. Creatures, deceased individuals, receipts and history are retained. Prior SQL migrations 001–003 and creature schema v2 are unchanged.
- Concurrent identical/out-of-order snapshots acknowledge the current facts without duplicating memberships or extending an old lease. An older different snapshot cannot undo a newer pause or credential change. Membership identifiers cannot be reassigned between classes. Class → sorted membership → session locking coordinates authorization and revocation.
- Every assertion, code exchange and private game request requires an enabled, unexpired school class lease. Freshness is rechecked after membership and final flow/session lock waits, so a wait cannot extend permission or yield a negative session deadline. Session deadline headers include this earlier expiry. No fresh school verification means access stops; it never silently trusts an old active row.
- `mode=checklings-admin` is a school-teacher-only panel for opening, pausing and refreshing configured classes. Each class starts paused. Pausing sends a disabled empty snapshot and works independently of an oversized, duplicate or otherwise unhealthy roster. An unconfirmed push reports the local setting and the failure to confirm remotely. This is school-side access control, not a general game teacher role or PvP/lethal settings interface.
- School launch pages clear their PIN input immediately after submission, clear selection/link state on Done, hiding or page exit, and reject late responses after clearing. They contain no external assets or browser storage. A return link targets the top-level page and expires with its code. The game retains Batch 04's cookie/CSRF/Done protections.

## Access freshness: exact limits

The school signs leases lasting at most **120 seconds**, beginning at its snapshot time. A successful student launch refreshes that whole class from current roster facts; the teacher can explicitly refresh from the private access panel. There is **no background trigger, automatic roster-change hook, game polling, or per-turn school request** in this batch.

A confirmed pause, PIN update or roster sync revokes affected game sessions transactionally. A roster change that has not yet been pushed does **not** propagate instantly: an existing lease may remain valid until its original expiry, at most two minutes. If a push fails, that bound still applies. Pausing locally prevents new school launches immediately. Reopening does not revive revoked sessions. A valid game session still has a two-minute idle and fifteen-minute absolute cap; its usable duration is additionally limited by fresh class authorization.

This is deliberately a bounded staging authorization mechanism. An unattended class will require a fresh launch or explicit teacher refresh when its lease ends. A usable renewal approach must be demonstrated during hosting/Workspace staging before sustained classroom gameplay is claimed. The initial snapshot limit is **35 active students per class**; larger classes fail explicitly before issuance rather than truncating authorization. Inactive rows are omitted, and omission revokes existing memberships. Scale/chunked snapshots remain later work.

## Private configuration and release boundary

The optional school path is off unless private Script Property `CHECKLINGS_BRIDGE_CONFIG` has `enabled: true` and valid configuration. Nothing writes this property automatically. It contains:

| Field | Requirement |
|---|---|
| `issuer`, `audience`, `tenantId` | Stable opaque identifiers matching the dedicated broker configuration |
| `gameOrigin` | Exact HTTPS origin of an approved separate `*.netlify.app` host or `checklings.grant-desk.com`; no path, credentials, query, port or arbitrary return URL |
| `classPeriods` | Explicit allowlist of exact existing class labels; max 20 |
| `assertionKey`, `flowKey`, `schoolKey`, `identityKey` | Four different, independently generated 32-byte random values encoded as 43-character base64url strings; never commit them |

**Key representation matters:** Apps Script uses these encoded strings as UTF-8 HMAC keys. The Node configuration must use `Buffer.from(encodedKey, 'utf8')`, **not** `Buffer.from(encodedKey, 'base64url')`. The four keys are separate from the Hall Pass salt. Protect the identity key and durable `ck-bridge-class:` revision properties in backups; replacing them can orphan mappings or make restored snapshots stale. Coordinated key rotation/recovery needs an operator rehearsal, not a reset of student state.

`createSchoolService` is supplied to `createGameHandler` as `school`. `/bridge/school` accepts only strict signed snapshots through the private server transport; browser Origin/Cookie/Fetch Metadata requests are refused. UrlFetch uses fixed paths, certificate verification, no redirect following, bounded response parsing and generic error text. No raw credential/assertion/error is logged by this implementation. The existing shared request limiter covers the bridge; school-egress rate/abuse tuning still needs staging.

All school network calls run after the short workbook lock is released. No game call is inserted into attendance, pass, queue, PIN rotation, roster-edit commits or background maintenance. Normal `/exec` modes and `Index.html`, `ReleaseChecks.gs`, `ReleaseCheck.html` and `appsscript.json` remain unchanged. Source is still five files; the new pages are generated within `Code.gs`.

A source push or site deployment does not update Apps Script.
