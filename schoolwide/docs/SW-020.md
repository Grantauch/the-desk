# SW-020 — Database foundation

Status: implementation batch. No production activation.

## Objective

Extend the verified SW-010 PostgreSQL foundation into the durable relational base required by SW-030 auth/RBAC and SW-040 schedule/policy work without touching the classroom production system.

## Scope implemented

- append-only migrations after frozen SW-010 migration 001
- organization/district boundary while retaining school as the operational tenant
- academic years and terms
- organization-scoped staff identity and role integrity
- canonical student alias/local-number foundations
- section academic-year ownership and broader section-staff role vocabulary
- ACTIVE/INACTIVE/PENDING_REVIEW enrollment lifecycle
- schedule profiles/periods
- explicit school calendar days
- destinations
- school policy sets/values, section overrides and student access rules as storage only
- append-only audit hardening
- idempotency-key and transactional-outbox primitives
- fictional two-school database fixtures and executable PostgreSQL constraint tests
- schema contract documenting ownership/provenance/lifecycle/future behavior owner

## Explicitly not implemented

No Google OAuth, staff session/auth middleware, schedule resolution, policy precedence, PIN verifier/action proof, check-in, Hall Pass request/queue/return, Classroom sync, legacy importer, real-data migration, persistent cloud environment, deployment or route cutover.

## Verification gate

SW-020 is verified only when:

1. clean PostgreSQL 18 migration succeeds;
2. a second migration run is a no-op;
3. database integration tests prove tenant/identity/lifecycle/date/audit/outbox constraints;
4. Schoolwide firewall/typecheck/tests/build pass;
5. the existing full GrantDesk site/Hall Pass gate remains green;
6. final diff contains no legacy production runtime change;
7. no real student data, PIN material, OAuth secret or production identifier is introduced.

## Production firewall

The existing Apps Script Version 18 Hall Pass/Daily Check-In deployment, private workbook, stable `/exec`, public student routes and current `main` production behavior remain independent and authoritative for Grant's classroom. SW-020 has no write path to them.
